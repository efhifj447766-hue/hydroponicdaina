# HydroSense แบบ MQTT (ไม่ต้องมีเซิร์ฟเวอร์)

```
เซนเซอร์ → ESP32 ──MQTT/TCP 1883──> broker.emqx.io <──WebSocket 8083/8084── หน้าเว็บ (mqtt.min.js)
```

## ไฟล์ในชุด

| ไฟล์ | ฝั่ง | หน้าที่ |
|---|---|---|
| `esp32/hydrosense_esp32_mqtt/hydrosense_esp32_mqtt.ino` | ESP32 | อ่าน pH, EC, DS18B20, DHT22 ส่งขึ้น MQTT, รับคำสั่ง, ต่อใหม่อัตโนมัติ |
| `esp32/hydrosense_esp32_mqtt/config.h` | ESP32 | **ไฟล์ตั้งค่า** Wi-Fi, Broker, Topic, ขา GPIO, ค่า calibrate |
| `web/js/config.js` | เว็บ | **ไฟล์ตั้งค่า** (เพิ่มบล็อก `MQTT`) |
| `web/js/data-source.js` | เว็บ | ชั้นรับส่งข้อมูล เปลี่ยนจาก REST/WebSocket เป็น MQTT |
| `web/js/app.js` | เว็บ | แก้เล็กน้อย: การ์ด "ควบคุมอุปกรณ์" ในหน้า "อุปกรณ์", ค่า RSSI/วันสอบเทียบ |
| `web/index.html` | เว็บ | เพิ่ม `<script>` ของ `mqtt.min.js` |
| `web/sw.js` | เว็บ | อนุญาตแคช `mqtt.min.js` จาก CDN |
| `web/css/styles.css`, `web/manifest.webmanifest`, `web/icons/` | เว็บ | **ไม่ได้แก้** หน้าตา UI, ธีม, กราฟ เหมือนเดิม |

หมายเหตุ: โปรเจกต์นี้ไม่มีไฟล์ `charts.js` และ `alerts.js` กราฟอยู่ใน `app.js` (ไม่ได้แก้) ส่วนตัวตัดสินแจ้งเตือนเดิมอยู่ฝั่ง backend ซึ่งโหมดนี้ไม่ใช้

## 1) จุดที่ต้องกรอก — ฝั่ง ESP32 (`config.h`)

| ค่า | ใส่อะไร | เอามาจากไหน |
|---|---|---|
| `WIFI_SSID` | ชื่อ Wi-Fi | Wi-Fi 2.4 GHz ที่บอร์ดต่อได้ (ไม่รองรับ 5 GHz) |
| `WIFI_PASS` | รหัส Wi-Fi | ของคุณ |
| `MQTT_HOST` | `broker.emqx.io` | **ต้องตรงกับเว็บ** `MQTT.HOST` |
| `MQTT_PORT` | `1883` | พอร์ต TCP ของ Broker (เว็บใช้ 8083/8084 คนละพอร์ตแต่เป็น Broker เดียวกัน) |
| `MQTT_USER`, `MQTT_PASS` | เว้นว่าง | broker สาธารณะไม่ต้องใช้ ถ้าใช้ EMQX Cloud ของตัวเอง ใส่ username/password ที่สร้างในหน้า Authentication ของ EMQX |
| `CLIENT_ID_PREFIX` | `hs-esp32-` | ตั้งเองได้ บอร์ดต่อท้ายด้วยเลขจากชิปให้เอง ต้องไม่ซ้ำกับ Client ID ใดบน Broker (ห้ามเหมือนของเว็บ `hs-web-`) |
| `TOPIC_PREFIX` | เช่น `hydrosense/k7f3q9x2` | **คิดค่าสุ่มเอง ต้องตรงกับเว็บ** `MQTT.TOPIC_PREFIX` เป๊ะๆ บอร์ดจะไม่ต่อ MQTT ถ้ายังเป็น `CHANGE-ME` |
| `TOPIC_READINGS/STATUS/STATE/CMD` | ใช้ค่าเดิม | ต้องตรงกับ `MQTT.TOPICS` ในเว็บ ถ้าไม่แก้ทั้งสองฝั่งก็ไม่ต้องแตะ |
| `PUBLISH_MS` | `30000` | รอบส่งค่า (มิลลิวินาที) |
| `PIN_DS18B20`, `PIN_DHT`, `PIN_PH`, `PIN_EC` | ค่าเริ่มต้น 4, 5, 34, 35 | หมายเลข GPIO ที่คุณต่อสายจริง ขาแอนะล็อกต้องเป็น ADC1 (32–39) |
| `PIN_RELAY`, `PIN_LED` | ค่าเริ่มต้น 26, 2 | ขาที่ต่อรีเลย์/LED |
| `RELAY_ON_LEVEL` | `HIGH` หรือ `LOW` | ดูสเปกโมดูลรีเลย์ โมดูลส่วนใหญ่เปิดเมื่อสั่ง LOW |
| `RELAY_MAX_ON_MS` | `600000` | ตัดรีเลย์เองเมื่อค้างเกินกำหนด 0 = ปิดฟีเจอร์ |
| `PH_MV_AT_7`, `PH_MV_AT_4`, `EC_STD_*` | ค่าตัวอย่างต้องแทนที่ | วัดจริงด้วยน้ำยามาตรฐาน: พิมพ์ `raw` ใน Serial Monitor (115200) ตอนจุ่มน้ำยาแล้วจดค่า mV |

## 2) จุดที่ต้องกรอก — ฝั่งเว็บ (`web/js/config.js` บล็อก `MQTT`)

| ค่า | ใส่อะไร | เอามาจากไหน |
|---|---|---|
| `ENABLED` | `true` | เปิดโหมด MQTT |
| `HOST` | `broker.emqx.io` | **ต้องตรงกับบอร์ด** `MQTT_HOST` |
| `PORT_WS` | `8083` | ใช้เมื่อเปิดเว็บผ่าน `http://` หรือ `localhost` |
| `PORT_WSS` | `8084` | ใช้อัตโนมัติเมื่อเปิดเว็บผ่าน `https://` (GitHub Pages, Netlify ฯลฯ และตอนติดตั้งแอป) |
| `PATH` | `/mqtt` | พาธ WebSocket ของ EMQX |
| `USERNAME`, `PASSWORD` | เว้นว่าง | ถ้าใช้ EMQX Cloud ใส่ที่นี่ ระวัง: ค่านี้ทุกคนที่เปิดเว็บอ่านได้ |
| `CLIENT_ID_PREFIX` | `hs-web-` | เว็บต่อท้ายเลขสุ่มให้เองทุกแท็บ ไม่ต้องกำหนดเลขเอง |
| `TOPIC_PREFIX` | เช่น `hydrosense/k7f3q9x2` | **ต้องตรงกับบอร์ด** `TOPIC_PREFIX` เป๊ะๆ เว็บจะไม่เชื่อมต่อถ้ายังเป็น `CHANGE-ME` |
| `TOPICS.*` | ใช้ค่าเดิม | ต้องตรงกับ `TOPIC_*` ในบอร์ด |
| `CONTROLS[].key` | `relay1`, `led` | **ต้องตรงกับชื่ออุปกรณ์ในบอร์ด** (`/cmd/relay1`, `/cmd/led`) ส่วน `label` ตั้งข้อความที่โชว์ได้อิสระ |
| `KEEP_DAYS` | `7` | จำนวนวันที่เก็บประวัติกราฟในเบราว์เซอร์ |
| `SENSORS[].field` | `ph, ec, water_temp, air_temp, humidity` | ต้องตรงกับชื่อฟิลด์ใน JSON ที่บอร์ดส่ง (ค่าเริ่มต้นตรงกันแล้ว) |

## 3) ค่าที่ต้องตรงกันเป๊ะๆ ระหว่างบอร์ดกับเว็บ

| บอร์ด (`config.h`) | เว็บ (`config.js`) | หมายเหตุ |
|---|---|---|
| `MQTT_HOST` | `MQTT.HOST` | ที่อยู่ Broker |
| `TOPIC_PREFIX` | `MQTT.TOPIC_PREFIX` | **ตัวสำคัญที่สุด** ผิดตัวเดียวข้อมูลไม่มา |
| `TOPIC_READINGS`, `TOPIC_STATUS`, `TOPIC_STATE`, `TOPIC_CMD` | `MQTT.TOPICS.readings/status/state/cmd` | รวมเครื่องหมาย `/` หน้าและหลัง |
| ชื่อ `relay1`, `led` ใน `.ino` | `MQTT.CONTROLS[].key` | |
| ชื่อฟิลด์ JSON (`ph`, `ec`, `water_temp`, `air_temp`, `humidity`) | `SENSORS[].field` | |

**ต้อง "ไม่เหมือนกัน"**: Client ID ของบอร์ดกับของเว็บ (ชุดนี้แยกคำนำหน้าให้แล้ว)
**พอร์ตไม่ต้องตรงกัน**: บอร์ดใช้ 1883 เว็บใช้ 8083/8084 เพราะเป็นคนละช่องทางเข้า Broker ตัวเดียวกัน

## 4) ขั้นตอนใช้งาน

1. คิด `TOPIC_PREFIX` แบบสุ่ม เช่น `hydrosense/` + 8 ตัวอักษรที่คุณสร้างเอง ใส่ทั้ง `config.h` และ `config.js`
2. Arduino IDE ติดตั้งไลบรารี PubSubClient, ArduinoJson (7.x), OneWire, DallasTemperature, DHT sensor library, Adafruit Unified Sensor → แก้ `config.h` → อัปโหลด → เปิด Serial Monitor 115200 ต้องเห็น "ต่อ MQTT... สำเร็จ" แล้วเห็น JSON ทุก 30 วินาที
3. เปิดเว็บ: ทดสอบในเครื่องด้วย `python3 -m http.server 8080` ในโฟลเดอร์ `web` แล้วเข้า `http://localhost:8080` หรืออัปโหลดโฟลเดอร์ `web` ขึ้น GitHub Pages / Netlify (ได้ HTTPS ฟรี)
4. แถบบนเว็บต้องขึ้น "ออนไลน์ · อัปเดตเมื่อ … วินาทีที่แล้ว" และตัวเลขบนการ์ดตรงกับ Serial Monitor
5. ไปหน้า "อุปกรณ์" (ไอคอนชิป) กดสวิตช์ "LED ทดสอบ" ต้องเห็น LED ติด และสวิตช์เปลี่ยนเมื่อบอร์ดรายงานสถานะกลับมา
6. ติดตั้งแอปบนมือถือ: เปิดผ่าน HTTPS แล้วกดเมนู ⋮ → ติดตั้งแอป (iPhone: ปุ่มแชร์ → เพิ่มไปยังหน้าจอโฮม)
7. แก้ไฟล์ใน `web/` แล้วเปลี่ยนเลข `hydrosense-v5` ใน `sw.js` เพื่อให้เครื่องที่ติดตั้งไว้อัปเดต

## 5) พฤติกรรมที่ควรรู้ (เพราะไม่มีเซิร์ฟเวอร์)

- **ประวัติกราฟ**: เก็บในเบราว์เซอร์ (localStorage) เฉพาะข้อมูลที่รับตอนเปิดหน้าเว็บอยู่ ช่วงที่ปิดเว็บกราฟจะเป็นช่องว่าง และแต่ละเครื่อง/เบราว์เซอร์มีประวัติของตัวเอง ถ้าต้องการประวัติครบต้องมีฐานข้อมูลฝั่งเซิร์ฟเวอร์ (ชุด `hydrosense-full` ที่ให้ไปก่อนหน้า)
- **ค่าล่าสุด**: บอร์ดส่งแบบ retained เว็บที่เปิดทีหลังจึงได้ค่าล่าสุดทันที ถ้าค่าเก่าเกิน 5 นาทีเว็บแสดง "ออฟไลน์"
- **การตั้งค่า** (ช่วงเป้าหมาย/เกณฑ์เตือน) เก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น
- **การ์ด "การแจ้งเตือนล่าสุด"** จะมีรายการเมื่อมีอะไรส่ง JSON `{"ts":..,"sensor":"ph","level":"warn","message":"..."}` มาที่ `<TOPIC_PREFIX>/alerts` เท่านั้น ตอนนี้บอร์ดไม่ได้ส่ง และไม่มีการส่ง LINE/อีเมล (ต้องมีเซิร์ฟเวอร์)
- ปุ่ม "ส่งข้อความทดสอบ" ในหน้าตั้งค่าส่งคำสั่ง `/cmd/test` ให้ LED บนบอร์ดกระพริบ 3 ครั้ง ปุ่ม "บันทึกการสอบเทียบใหม่" ส่ง `/cmd/calibrate` (บอร์ดแค่พิมพ์ใน Serial) และจดวันที่ไว้ในเบราว์เซอร์

## 6) ความปลอดภัย (อ่านก่อนต่อรีเลย์กับโหลดจริง)

`broker.emqx.io` เป็น Broker สาธารณะที่ **ไม่มีรหัสผ่าน** ใครรู้ชื่อ topic ก็อ่านค่าและสั่งงานได้ การตั้ง `TOPIC_PREFIX` แบบสุ่มช่วยได้แค่ให้เดายาก ไม่ใช่การป้องกันจริง และบริการสาธารณะไม่รับประกันความเสถียร

- ใช้ชุดนี้ทดลองกับ LED หรือโหลดที่เสียหายไม่ได้ ห้ามใช้ควบคุมอุปกรณ์ที่อันตราย (ไฟแรงสูง ฮีตเตอร์ ปั๊มที่ล้นแล้วเสียหาย) โดยไม่มีวงจรป้องกันอิสระ
- รีเลย์เริ่มต้นเป็นปิดเสมอ และมีตัวตัดอัตโนมัติ (`RELAY_MAX_ON_MS`) แต่ไม่ใช่ระบบความปลอดภัย
- ก่อนใช้งานจริงควรย้ายไป EMQX Cloud/Broker ส่วนตัวที่มี username/password และ ACL (จำกัดให้เว็บ subscribe และ publish ได้เฉพาะ topic ที่จำเป็น) และใช้ TLS (บอร์ดพอร์ต 8883) โดยทราบว่ารหัสที่ใส่ใน `config.js` ใครเปิดเว็บก็เห็นได้
